🧭 Conclusion et perspectives

Ce projet industrialise un modèle issu d'une phase Data Science exploratoire antérieure (voir Contexte DS) — la conclusion ci-dessous porte sur l'industrialisation MLOps elle-même (Phases 1→4), pas sur la phase exploratoire d'origine.

Ce qu'on a construit

Un notebook de recherche ne suffit pas à mettre un modèle entre les mains d'un utilisateur réel — il a fallu construire tout un système autour.

🧩 Microservices HTTP 🗃 Données & modèles versionnés (DVC/MLflow) 🔒 API sécurisée (clé, rate limiting) ⚙️ CI/CD lint → tests → build → déploiement 📈 Monitoring en prod

Ce qu'on a appris en le construisant

Un test en lot sur des radios réelles a montré que le backend confondait systématiquement trois classes sur quatre :

backend/config.py (avant fix)

COVID → Lung_Opacity → Normal → Viral_Pneumonia
ordre alphabétique

⚠️≠

params.yaml / dvc.lock (réel)

COVID → Normal → Viral_Pneumonia → Lung_Opacity
ordre figé à l'entraînement

35%
→
78%
accuracy sur le même lot de 60 radios réelles, après correction d'une ligne

Invisible sur un exemple isolé, flagrant sur une matrice de confusion. Le vrai enseignement est méthodologique : un modèle qui répond n'est pas un modèle qui répond juste — sans test de bout en bout sur des données réelles, ce bug serait passé inaperçu jusqu'à la démo.

D'autres frictions, plus ordinaires, ont jalonné le projet : un test de déploiement CI intermittent (root-causé et corrigé), une image Docker périmée révélée seulement sous Kubernetes, un service MLflow qui dépasse sa limite mémoire selon le nombre de cœurs CPU (cause identifiée, correctif pas encore appliqué). Le genre de choses qu'on ne voit qu'en poussant le système au-delà du cas nominal.

⚠️ Ce projet reste une démonstration MLOps — pas un dispositif médical, pas destiné à un usage clinique en l'état.

La suite

Le monitoring en place (Grafana, alertes Prometheus, rapport de dérive Evidently) donne déjà de la visibilité — la prochaine étape logique est de le rendre continu plutôt que déclenché à la main, puis d'y brancher un ré-entraînement semi-automatique quand la dérive dépasse un seuil. Le déploiement Kubernetes, préparé mais pas encore lancé, et une documentation de transfert (ADRs, runbooks) restent les deux chantiers qui feraient passer ce projet de « démonstration convaincante » à « système que l'équipe suivante peut reprendre sans nous ».
