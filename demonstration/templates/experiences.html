Expériences : MLflow local & DagsHub

Chaque entraînement conserve une trace locale complète, puis la réplique dans DagsHub pour partager les résultats, comparer les runs et retrouver les modèles.

MLflow local
Source principale du tracking : paramètres, métriques par epoch, artefacts et Model Registry restent disponibles dans la stack locale.
Ouvrir MLflow local
Disponible avec make start-all.
DagsHub
Miroir optionnel des runs MLflow : expériences, courbes en direct, modèles et versionnage des données accessibles à l'équipe.
Ouvrir DagsHub
Activé quand les variables DAGSHUB_* sont configurées.

Un run, deux espaces de suivi

Entraînement DVC

train.py ou train_segmentation.py crée le run et enregistre les données de suivi.

→

MLflow + DagsHub

MLflow local reçoit le run principal. DagsHub reçoit le même historique comme miroir non bloquant.

Suivi pendant l'entraînement

DémarrageCréation de l'expérience et du run.
Chaque epochLoss et métriques validation alimentent les courbes en direct.
Fin du runParamètres, configuration et modèle sont conservés comme artefacts.
PromotionUn modèle qui franchit son seuil rejoint le Model Registry.

Si DagsHub est indisponible, l'entraînement et le tracking local continuent : le miroir distant est volontairement secondaire.
